# Архитектура UniSpace AI

## Принципы

1. **Ядро без фреймворка.** `models`, `storage`, `ai`, `services` не импортируют FastAPI. Их можно запускать и тестировать отдельно.
2. **API — тонкий слой.** Роутеры только валидируют вход, вызывают сервисы и сохраняют результат.
3. **LLM опционален.** Каждая AI-функция имеет детерминированный офлайн-фолбэк, поэтому платформа работает без ключа и в CI.
4. **Время как параметр.** Сервисы принимают `today`, поэтому результаты воспроизводимы в тестах.

## Слои

```
HTTP ──► api/routers ──► services ──► models
                │            │
                │            └──► ai (LLMClient)
                └──► storage (Store)
```

| Слой | Ответственность |
|---|---|
| `api/` | Роуты, DI-контейнер (`Container`), обработка ошибок (404 для `NotFoundError`, 502 для `LLMError`) |
| `services/` | `planner`, `quiz`, `flashcards`, `materials`, `progress`, `deadlines`, `text` |
| `ai/` | `LLMClient` (протокол), `AnthropicLLM`, `OfflineLLM`, `Tutor` |
| `storage.py` | `Collection[T]` и `Store`; атомарная запись JSON |

## Ключевые алгоритмы

**Планировщик.** Каждый день (кроме воскресенья) бюджет минут делится между предметами. Вес предмета = `(6 − уровень) × (1 + 10 / (дней_до_экзамена + 1))`. Чтобы слабо взвешенные предметы не выпадали, учитывается «долг» — разница между положенным и полученным временем; в день попадает не более трёх предметов.

**Интервальные повторения (SM-2).** Оценка 0–5; при оценке < 3 серия сбрасывается, интервал — 1 день; иначе интервалы 1 → 6 → `интервал × ease`. `ease` не опускается ниже 1.3.

**Генерация тестов.** С LLM: промпт с требованием JSON, валидация через Pydantic, при любой ошибке — фолбэк. Без LLM: выбор предложений средней длины, замена ключевого слова пропуском, дистракторы из других ключевых слов.

**Безопасность AI.** Текст материала передаётся модели как данные в ограничителях `<<< >>>` с явной инструкцией не исполнять команды из него.

## Известные ограничения

- Единое глобальное пространство данных (нет пользователей).
- Блокировка только на запись файла; для нагрузки нужна БД.
- Даты считаются по часовому поясу сервера.
